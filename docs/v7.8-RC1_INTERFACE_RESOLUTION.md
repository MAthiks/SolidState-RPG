# Solid State v7.8-RC1 — Interface Rule Resolution

Status: VERIFIED SPECIFICATION RESOLUTION
Scope: `develop` / v7.8-RC1 only
Baseline v7.7 remains unchanged.

## Conflict

The inherited v7.7 continuity snapshot records:

- 4 proposed numbered actions
- 1 free action

The v7.8-RC1 candidate state explicitly introduces a player-interface rule update, and the active Development Directive v1.1 defines the new contract.

## Authoritative RC1 rule

### NORMAL / LIBRE — default

- End a decision with an open invitation such as `Que fais-tu ?`
- Do not automatically display contextual action choices.
- A help control may be available, but it is UI and not a narrative action.

### FACILE / ASSISTÉ — per player, on request

- Keep the same open invitation.
- On help request, display exactly 3 contextual suggestions + 1 free action.
- Suggestions are not exhaustive.
- Suggestions may use only `PLAYER_KNOWLEDGE_ONLY`: what the investigator knows, sees, hears, or may reasonably deduce.
- Keeper-only state, hidden clues, future events, unknown solutions and protected scenario truth are forbidden inputs.

## Precedence

For Solid State v7.8-RC1 and later descendants of this candidate:

`candidate_state.player_interface_rule_update` + Development Directive v1.1

supersede the inherited v7.7 `player_interface_rules.end_of_sequence_choices` field.

This is a forward migration rule only. It does not rewrite or falsify the historical v7.7 snapshot.

## Regression evidence

A separate autonomous document-grounded interface report records PASS on the documented contract, including 10,000/10,000 stress runs.

The repository RC1 specification harness also tests this rule deterministically and under randomized stress.

## Release condition

Any executable RC1 implementation MUST conform to this resolved rule before it may be promoted. A runtime that automatically restores the inherited 4+1 menu fails RC1 certification.
